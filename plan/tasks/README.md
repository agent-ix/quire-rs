## Coordination Rules

1. **Do not skip gates.** Gate failure means stop — diagnose before adding downstream work.
2. **Critical-path tasks merge serially.** Track B/C/D can merge as they complete (after their gates).
3. **Track C was BLOCKED until G2 passed** (now released).
4. **Track D was BLOCKED until G2 passed and the v0.2 spec was approved** (now released; G4 PASS).
5. **Update this README on each transition.** Status drift breaks coordination.
6. **Each task starts with the failing test set** (TDD red), then implementation (green), then refactor + benches.
7. **Spec changes during implementation** require a CR — do not silently edit `~/dev/quire-rs/spec/` from a task branch.
8. **NFR-003 (zero unsafe), NFR-004 (license), NFR-005 (error shape), NFR-006 (determinism)** are cross-cutting — every task is responsible for not breaking them.
