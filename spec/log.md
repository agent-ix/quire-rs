# Update Log

## History

* **2026-08-17** — **[FR-054](./functional/FR-054-verification-method-catalog.md) Verification-Method Catalog** (new FR): "how should this requirement be verified" gets a machine-readable answer. The vocabulary was scattered and prose-bound — ISO 29148's `Inspection | Analysis | Demonstration | Test` lived only inside two `spec-artifacts-iso` lint rules, techniques lived in `traceability.vocabularies.test_type`, and quoin's `spec-evidence-analysis` skill assigned a method per requirement from a **skill-local prose table that no manifest declares and no code reads**. Nothing could advise a method, and nothing could check that a chosen one was honoured. `verification_catalog:` is a top-level map of method id → {name, class, definition, evidence kind, applicability, tooling}, merged **first-wins** across modules like every other registry, for the NFR-006 reason: the merged answer must not depend on load order. Unlike the other vocabularies a re-declared id **is** reported (`DuplicateVerificationMethod`) — two modules disagreeing about what `mutation-testing` means is a collision an operator must see, not an idempotent re-declaration. Two deliberate non-decisions keep it general. **`class` is a free string**, not a closed IADT enum: this ecosystem classifies by 29148, and an external user classifying by 29119-4 technique family or by assurance level must be able to; an engine-side enum would make the catalog agent-ix's rather than theirs (CON-1). **`applicability:` is opaque** — stored and surfaced, never interpreted (CON-2) — because deciding which requirement a rule matches is the advisor's judgement, and an engine that understood `property_shapes` would owe an understanding of every axis a future module invents; the fixture declares `forbidden_dependency_edges` precisely to prove a rule name the engine has never heard of survives verbatim. The catalog is then **addressable as a vocabulary**: `Registry::column_vocabulary` matched exactly one hardcoded name (`test_type`) and now answers `verification_method` and `verification_class` too, both **derived from the merged catalog at construction** rather than authored a second time (CON-4) — which is what makes it a single source instead of a fourth copy. **`from_vocabulary` on `LocatorAssert` deliberately does not ship here**, the decision agent-ix/quire-rs#133 left to Specify: resolving a vocabulary *reference* inside an assert has to happen after the cross-module merge, which means either threading a `Registry` through `evaluate_assert` — a public API signature change on the per-document validation path — or rewriting compiled archetypes at registry construction; each is a real change with its own acceptance surface, and bundling either in would make one release carry two unrelated risks, against a duplication (`column_choices.Type` vs `test_type`) that is currently held honest by a passing `spec-artifacts-process` test rather than silently rotting. The *lookup* half ships, so process#35 can reconcile toward one source immediately; the assert-side key is filed separately with the design recorded. Matrix: TC-844..TC-853, **529/529**, and of 523 rows 221 ✅ / 277 🚧 / 25 retired. Closes agent-ix/quire-rs#133 (epic #81, P1).

* **2026-08-17** — **[FR-053](./functional/FR-053-obligation-record.md) Obligation Record** (new FR): the quire↔quoin contract ADR 0011 names and neither side had. `quire properties --json` carried property *shapes*, FR-050 coverage carried the AC→TC *rollup*, and neither carried a **content hash** — so nothing downstream could see a suspect link, evidence bound to a statement that has since been reworded — or a **verification method**, so nothing could see an analysis-method requirement discharged by a unit test. An obligation is **derived, never authored**: choosing an acceptance criterion's verification method *is* minting it, and the engine reads what the author already wrote. Which rows state obligations is module data — a `traceability.obligations:` block naming, per source, the statement/method/criticality columns and a parameter map — so the engine knows the *shape* and never a column name, a method name or an archetype (CON-1). Sources resolve their minting documents exactly one of two ways, and **both-or-neither is a load-time error** rather than a source that silently yields nothing: `target:` inherits archetype, section and id column from a declared trace target, so an acceptance criterion is not declared twice and the obligation id is by construction the id the rollup and every trace tag already key on; `archetype:` + `section:` + `id_format:` covers a table whose rows mint no id of their own. That second form exists for a reason worth stating: the NFR **`Measurement and Evaluation`** table is present in 19 of 19 of this repo's NFRs, every row is a quantified obligation (metric, target, threshold, method), and none has an `ID` column — modelling it here is what lets a performance budget be discharged, ratcheted and reported by the same machinery as a functional criterion instead of by a parallel mechanism that drifts. **The hash deliberately does not reuse the CR-017 mask**, which agent-ix/quire-rs#82 proposed: `mask_code_spans` replaces a code span's *contents* with `x` so a quoted keyword reads as a mention rather than a use — right for grammar detection, catastrophic for a hash, because ``reject a `foo` token`` and ``reject a `bar` token`` mask to the same string and a backticked identifier is usually the most load-bearing token in a criterion. A suspect-link detector built on it would stay silent through the exact rename it exists to catch. Normalization is NFC + trim + whitespace-run collapse, which gives the property the ticket actually wanted — a re-wrap does not churn the hash — without ever equating two statements a reader would read differently (CON-3: the hash is computed from the statement alone, never the id, path, line or method, because a detector that fires on a file move is one that gets switched off). Surface adds no command: the record rides `AcClassification.obligation` and `CoverageReport.obligations`, the nested form omitting `id`/`statement`/`document` because the record and its enclosing object already carry all three. Both are `skip_serializing_if` empty, so **a module that has not adopted obligations serializes exactly as before** — the TC-824 byte-identity baseline passes untouched, which is FR-050-AC-7 held rather than asserted. Matrix: TC-831..TC-843, **519/519**, and of 513 rows 211 ✅ / 277 🚧 / 25 retired. Closes agent-ix/quire-rs#82 (epic #81, P1).

* **2026-08-07** — **CR-028**: acceptance criteria gain a **second, orthogonal shape axis** — property shape — in new [FR-052](./functional/FR-052-acceptance-criteria-property-classification.md) (agent-ix/quire-rs#20, Phase B of the umbrella agent-ix/quire-rs#17). Spec-only; no engine change lands in this slice. The program's goal is turning acceptance criteria into executable property-based tests, and CR-013 removed the route to them without replacing it: making the **assertion** canonical deleted the planned EARS→property extraction path, and nothing took its place, so no property test anywhere in the ecosystem is derived from an acceptance criterion today. The assertion is in fact the better substrate, not the worse one — a property test needs a generator domain, a precondition and an oracle, and EARS supplies only the last two (*"the system shall X"* quantifies over one system, not over a domain), whereas a quantified assertion carries all three: the determiner is the quantifier, the restrictive relative clause is the precondition, and the predicate is the oracle. FR-052 therefore classifies every criterion the `ac` grammar already binds to into a **closed** property-shape enum (`RoundTrip`, `Idempotence`, `Ordering`, `Invariant`, `Universal`, `ErrorCase`, `Lifecycle`, `Concurrency`, `Example`, `Unclassified`) under one **fixed total precedence** pinned in the spec rather than left to implementation, so structure outranks quantification and a universally quantified round-trip labels `RoundTrip`. For a `Universal` criterion it emits `{domain, precondition, oracle}` spans that are **statement-relative, never file-relative** (a supplement statement is synthesised by joining wrapped lines, so an offset does not index the file; only `line` is), and each span carries both byte offsets and its own text — offsets so the engine can assert the spans partition the statement, text because handing a UTF-16 consumer raw UTF-8 byte offsets is a defect generator, and the redundancy is checkable (FR-052-AC-6). Each record also carries `row_id` — without the criterion id the downstream generator cannot emit the tracking tag that coverage reconciliation keys on, and the chain would break silently — plus `signals`, the stable ids of what fired, which is the audit trail CR-019 asked for when it found the original sweep script had never been saved and the decision could not be re-derived. There is **no confidence float**: a float is unreviewable and invites the threshold tuning this program has already been burned by, so `Unclassified` is an explicit first-class outcome instead; and `extractable` is derived in exactly one place so the coverage column, any summary line and any downstream consumer cannot disagree about the ratio. `SchemaShaped` from the original report is **deliberately excluded** — its signal is repo state ("an OpenAPI schema exists"), not statement text, which would break determinism and corpus-comparability. Four constraints hold the boundaries: **CON-1** — classification never constructs a `GrammarFinding` and is never addressable by the FR-048 `grammar_severity` registry, so with no severity key there is no promotion path and `--strict` immunity holds by construction; a pass/fail gate on "is this criterion property-shaped" would invite authors to reword criteria to satisfy a checker instead of to describe the system, and it is the same failure mode as narrowing a check until its count looks comfortable. **CON-2** — the engine never names a test framework, harness or generator library; the shape→harness mapping belongs to the downstream `spec-correctness` work (quoin#46). **CON-3** — the shape enum is closed in the engine and extension happens by declaring idiom phrases, never by adding a shape, since a shape with no generator silently drops criteria. **CON-4** — a criterion's `extractable` value never depends on a module-declared idiom. That last one is the structural answer to whether the module `property_idioms:` registry is another open-set trap: CR-014's rule is that a closed set which *suppresses* is safe while an open set whose membership is *required* is not, which is what retired `no-observable-outcome` at ~13% sampled precision. Three of the four metamorphic classes are not actually open (invariant = English function words, idempotence = quantity adverbs, ordering = a small lexicon), and even round-trip has a closed structural signal — two operations composed plus an identity back-reference (`yields the input`, `returns the original`, `byte-identical`) — so **closed structural signals carry extraction coverage and the registry only refines labels**. A repo declaring nothing gets full reach; a missed idiom degrades a label to a less specific shape rather than dropping a criterion, and TC-790 pins that as a property test rather than an assumption.
