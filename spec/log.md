# Update Log

## History

* **2026-08-05** — **CR-018**: module discovery is sorted, closing a determinism hole under every first-wins merge. `load_modules` iterated `std::fs::read_dir` directly, whose order is unspecified, so which module won an `archetypes` / `lexicon` / `edge_types` / `grammar_severity` / `traceability` collision depended on filesystem layout. Three merge tests (TC-637, TC-668, TC-717) passed locally and failed on the CI runner for exactly that reason — the hole is invisible to a single-machine run, which is why it survived since FR-013. Discovery now sorts by path. Adds [NFR-006](./non-functional/NFR-006-determinism.md)-AC-5 + TC-762; matrix 443/443.

* **2026-08-05** — **CR-017**: the `ac` grammar stops confusing **mention with use**. A criterion that *quotes* a keyword as example data (``a statement with two `shall` clauses yields exactly one `non-singular` finding``) was classified as though it imposed an obligation — which accounted for every one of the seven `non-canonical-shape` findings standing against this repo's own spec, since FR-042/FR-043/FR-047 describe a grammar and therefore quote its keywords. Shape classification and obligation counting now read a copy in which each closed code span's contents are masked; the signal and lexicon checks still read the real words, so backticked identifiers and lexicon terms keep their suppressing effect. Masking exposed a second defect it would have made worse: supplement prose was segmented on `". "` without regard to code spans, cutting embedded examples (``` `EXPLAIN … SELECT ... ORDER BY col LIMIT 10` ```) in half and leaving unbalanced backticks — segmentation is now code-span aware, which is what makes the mask safe. Measured over the same 199-repo corpus as CR-014: **3,956 → 3,949** findings — 16 mention-only false positives removed, 9 true positives restored that the mask alone had hidden, 1 further true positive surfaced, and **no new finding in any other check**; this repo's own `ac` findings fall 10 → 2 (both remaining are `vague-response` on PyO3-parity criteria). Whether `ears` should adopt the same distinction is left open. Adds FR-047-AC-13 + TC-761; matrix 442/442.

* **2026-08-05** — **CR-015**: the traceability model becomes the single source for matrix column vocabularies, after the FR-003 ecosystem sweep found them declared in two places and drifting. [FR-050](./functional/FR-050-declarative-coverage-computation.md) gains: a `retired` status class and **leading-marker** classification, so `✅ Complete` and `⚠️ scale evidence deferred` class correctly while keeping the note that says why; a `vocabularies:` block (first entry `test_type`) that both a module's matrix contract and the rollup read; and two **default-off** reference normalizations, `expand_ranges` (`FR-001..FR-006` → concrete ids) and `strip_annotations` (a parenthetical qualifier contributes no reference). Sub-id kinds stay derived from the declared trace targets rather than enumerated — nothing is code-generated. Adds FR-050-AC-10..12 + TC-758..760; matrix 441/441.

* **2026-08-04** — **CR-014**: FR-047's two high-volume checks rebuilt after an ecosystem fit check (report: `~/dev/reports/2026-08-04-ac-grammar-fit.md`) ran the grammar over 5,027 requirement documents in 199 repos / 11,919 acceptance-criteria cells. `no-observable-outcome` fired on 51% of cells at ~35% sampled precision and `unclassifiable` on 43.5% at ~12%; the cause is structural — observability lives in an open-ended verb space (1,201 stems; the built-in 13 covered 14.5%), and declaring 73 corpus-mined verbs cut findings 60% but left precision unusable. The checks are therefore inverted: **`no-observable-outcome` becomes `vacuous-outcome`**, detecting a closed set of vacuous predicates (module-extensible via a new `vacuous_predicates` registry) suppressed by any concrete signal, lexicon term, or declared observable verb; **`unclassifiable` becomes structural** — no predicate at all. Measured over the same corpus: 25 and 39 findings (0.21% / 0.33%) against 11,269 before. The same evidence settled the **binding**: `ac` now covers every requirement archetype carrying an `Acceptance Criteria` table (FR/NFR/US/StR/IT), since FR-only reached 76.9% of AC-bearing documents and US/NFR criteria are the same shape. `observable_verbs` keeps its ADR-0009 role as the suppressor vocabulary. Also fixes three mechanical defects the check exposed: irregular/`-y` verb inflections, obligation clause-slicing dropping pre-modal concrete signals, and supplement-prose segmentation producing truncated fragments. Bullet-form AC sections remain unsegmented — recorded as future work.

* **2026-08-04** — **CR-013**: [FR-047](./functional/FR-047-acceptance-criteria-grammar.md) canonical acceptance-criteria shape changed from **EARS to the assertion**. The Gate G1 baseline over this repo's spec produced 340 `ac` findings across 44 FR documents, 322 of them `unclassifiable` — each a correct report that a declarative assertion is not an obligation, and only 18 substantive. Classified by quantifier instead of style, 50.8% of the corpus's 327 acceptance criteria are already property-shaped. An AC is a verification statement, not an obligation, so the canonical shape is the one that carries the test oracle. `unclassifiable` now means *structureless* (no modal, no Given/When/Then, no observable signal); `non-canonical-shape` now fires on obligation-shaped cells as well as GWT; shapes are `assertion | obligation | given-when-then | unstructured`. New **FR-047-CON-2** forbids making the canonical shape configurable — FR-048's per-check severity map is the opt-out. [FR-042](./functional/FR-042-requirement-grammar-check.md)'s non-goals bullet reworded accordingly (EARS remains the grammar for normative statements). Matrix: TC-707 and TC-751 rewritten; AC count unchanged at 438.
