## Stakeholder Need

`agent-ix/spec-artifacts-iso` and `agent-ix/spec-artifacts-app` already ship eight ISO archetypes (FR, NFR, StR, US, IT, TC, AC, CON) and two application archetypes (ApplicationSpec, MasterRequirements) using Python + Jinja2 with JSON-Schema-validated frontmatter. Hundreds of existing spec artifacts across the org were generated by that renderer.

For `quire-rs` to be a drop-in replacement, the Rust renderer SHALL produce **byte-identical output** to the Python reference, given the same validated input. Any whitespace normalization or formatting difference SHALL be explicitly documented and gated by a `--normalize` flag — never silent.

This is a regression-safety property, not an aspiration: existing artifacts should re-render byte-for-byte against their current source-of-truth, so a migration from the Python renderer to `quire-rs` does not produce noisy diffs.

## Priority

Must-Have

## Acceptance

- **StR-002-AC-1**: For each of the 10 archetypes (8 ISO + 2 App), a parity test fixture runs the Python Jinja2 reference and the Rust MiniJinja renderer on identical typed input and asserts byte equality of the markdown output.
- **StR-002-AC-2**: Any documented difference between Python and Rust output is captured as a known limitation in `spec/assets/render-parity-notes.md` with rationale.
- **StR-002-AC-3**: CI runs the parity test suite on every PR.
