## Stakeholder Need

`agent-ix/spec-artifacts-iso` and `agent-ix/spec-artifacts-app` already ship eight ISO archetypes (FR, NFR, StR, US, IT, TC, AC, CON) and two application archetypes (ApplicationSpec, MasterRequirements) using Python + Jinja2 with JSON-Schema-validated frontmatter. Hundreds of existing spec artifacts across the org were generated by that renderer.

For `quire-rs` to be a drop-in replacement, the Rust renderer SHALL produce **byte-identical output** to the Python reference, given the same validated input. Any whitespace normalization or formatting difference SHALL be explicitly documented and gated by a `--normalize` flag — never silent.

This is a regression-safety property, not an aspiration: existing artifacts should re-render byte-for-byte against their current source-of-truth, so a migration from the Python renderer to `quire-rs` does not produce noisy diffs.

## Rationale

This need exists because hundreds of existing spec artifacts across the org were generated by the Python + Jinja2 renderer that ships the eight ISO archetypes (FR, NFR, StR, US, IT, TC, AC, CON) and two application archetypes (ApplicationSpec, MasterRequirements) with JSON-Schema-validated frontmatter. For `quire-rs` to be a drop-in replacement rather than a source of churn, its output cannot diverge from that reference: existing artifacts must re-render byte-for-byte against their current source-of-truth. Any whitespace or formatting difference that crept in silently would turn a renderer migration into noisy, untrustworthy diffs across the whole corpus, which is why byte-identical output is treated as a regression-safety property rather than an aspiration.

## Validation Criteria

This need is considered satisfied when, for each of the 10 archetypes (8 ISO + 2 App), a parity test fixture runs the Python Jinja2 reference and the Rust MiniJinja renderer on identical typed input and asserts byte equality of the markdown output. Satisfaction is judged by every documented difference between the Python and Rust output being captured as a known limitation in `spec/assets/render-parity-notes.md` with rationale (never a silent divergence), and by CI running the parity test suite on every PR so regressions are caught before merge.
