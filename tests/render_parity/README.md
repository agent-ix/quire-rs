# Render Parity Suite (FR-012, Task 011 / 012 / 013)

This directory holds the corpus-driven render-parity fixtures used by
`tests/render_parity.rs`. Each entry in `corpus.yaml` points at a
**module root** to load into the test `Registry`, plus a list of
`(archetype, input.json, expected.md)` fixture triples to compare
byte-for-byte against `quire_rs::render_by_name`.

## corpus.yaml schema

```yaml
modules:
  - path: ./modules/demo        # relative to this directory
    name: demo                  # asserted module name (manifest's name field)

cases:
  - archetype: demo-item
    input: cases/demo-item-001.input.json
    expected: cases/demo-item-001.expected.md
```

All paths are resolved relative to `tests/render_parity/`.

## Bootstrap fixture (Gate G2 status)

A self-contained `demo` module ships under `tests/render_parity/modules/demo/`
with a single archetype + hand-authored `expected.md`. This proves the
harness wiring works without any external dependency.

The full 17-archetype sweep (Task 013) loads from `spec-artifacts-*`
clones and compares against expecteds regenerated by the Python
reference (`scripts/regenerate_parity_fixtures.sh`). Until that
regeneration is wired into CI on a fresh host (Python venv etc.), the
real-corpus cases are excluded from `corpus.yaml` and live in their
sibling repos.

## Adding a fixture

1. Drop `input.json` under `cases/`.
2. Regenerate `expected.md` via the Python reference (or hand-author
   for the bootstrap `demo` module).
3. Append a `cases:` entry to `corpus.yaml`.
4. `cargo test --test render_parity` should pass.

A failing case prints a unified diff so the divergence is obvious.

## Divergences

`divergences.md` records any documented byte-level differences between
`quire-rs` and the Python reference. v1 target is **zero** documented
divergences; any addition needs an explicit StR-002-AC-2 note.
