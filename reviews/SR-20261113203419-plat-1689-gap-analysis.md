# Gap analysis - PLAT-1689 edge target kinds under Strict (quire-rs PR 678)

## Summary

Ticket: PLAT-1689. Plan completion: not assessed. Scoped to the ACs this PR adds or amends and to
the ticket's three acceptance criteria, mapped to tagged tests and to `validate_edge_targets`.
I mutation-tested the assertions with seven source mutations of `validate_edge_targets`. Each
mutation was run against `edge_target_kinds`, `tc642` and `tc655`, and all seven were killed:

| Mutation | Killed by |
| --- | --- |
| M1 drop the archetype-name match | right_kind_by_archetype_name_passes |
| M2 fixed Warning tier instead of `posture_tier` | wrong_kind_is_error_under_strict_with_file_path |
| M3 document id as the finding path | wrong_kind_is_error_under_strict_with_file_path |
| M4 drop the target file path from the message | wrong_kind_is_error_under_strict_with_file_path |
| M5 bypass the `grammar_severity` map | severity_map_overrides_target_tier |
| M6 drop the object type/role match | tc642, tc655 |
| M7 restore the skip for targets with no `object:` | wrong_kind_..., severity_map_... |

Ticket AC mapping: (1) a wrong-kind target is an error under `--strict` with the file path:
FR-040-AC-13, covered. (2) Allow-list entries match archetype names: FR-040-AC-12, covered.
(3) Fixture tests where the right kind passes and the wrong kind and a dangling target fail:
covered, but the dangling test is tagged to the wrong AC (FND-002).

## Verdict

**PASS with findings: 2 medium, 1 low.** AC-12 and AC-13 are fully backed, and their key
assertions can fail. Gaps: AC-14 is only partly asserted. The dangling-target test is tagged to an
AC it does not exercise. There is no test for the inverse-edge message, the FR-041 path whose
message is wrong (code-review FND-002).

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | medium | FR-040-AC-14 requires `error`, `warning` and `off` to override the tier "in both postures". The test asserts three of the six combinations: Strict+warning, Strict+off and Okf+error. Okf+off, Okf+warning and Strict+error are unasserted. A reviewer probe found the behaviour correct for all three, so this is a coverage gap, not a defect. | tests/it/edge_target_kinds.rs:143-182 |
| FND-002 | low | `dangling_target_fails_strict` is tagged `FR-040-AC-12` but asserts only FR-026's `dangling-reference`. Dangling edges are explicitly skipped by Tier-2, so the test cannot fail through AC-12 and inflates AC-12's coverage. Tag it to the dangling criterion, or assert that no `disallowed-edge-target` is raised for it. | tests/it/edge_target_kinds.rs:184-195 |
| FND-003 | medium | The inverse-edge path (FR-041-AC-4) under the new kind match and message has no test. `tc655` checks only that the message contains the ids, under Okf. The wrong kind attribution in code-review FND-002 passes every existing test. | tests/it/inverse_edges.rs:286-350 |
