# Code review - PLAT-1689 edge target kinds under Strict (quire-rs PR 678)

## Summary

Ticket: PLAT-1689. PR head `1e5ba09`, scope `git diff origin/main...HEAD` (6 files, +260/-36).
Code-review with the rust-review lane folded in. Reviewer runs, all through `locked-build.sh`
in a detached scratch worktree: `cargo test --test it -- edge_target_kinds tc642 tc884 tc655 tc656`
(8 passed); clippy on the touched targets; seven source mutations of `validate_edge_targets`;
scratch probe tests (never committed); and an old-vs-new engine comparison. The comparison loaded
spec-artifacts-iso, spec-artifacts-process and spec-objects-architecture at `origin/main` as one
module set, and validated each repo's `spec/`, the process and architecture `design_edges`
valid/invalid fixtures, process `tests/fixtures/adr`, architecture `tests/fixtures/safety_class`
and quire-rs `spec/` under Strict and Okf.

## Verdict

**FAIL: 1 high, 2 medium, 3 low.** The core change does what the ticket asks. The target's own
`type:` is matched next to its `object:` type and roles. The tier is `posture_tier(posture)`, so
the finding is an error under Strict and a warning under Okf. It still goes through `report.route`,
so `grammar_severity` / `--severity` overrides work in both directions; a reviewer probe confirmed
Okf+off, Okf+warning and Strict+error as well as the tested combinations. The finding path is the
authored source's file. No archetype or field name is hard-coded beyond the engine-wide `type:` /
`object:` keys, and there is no compatibility layer or ceremony. Mutations M1-M7 were all killed
(see the gap-analysis SR).

Old vs new engine on real module corpora: the three repos' `spec/` trees and quire-rs `spec/`
show no new finding. The `invalid` design-edge fixtures move from warning to error under Strict,
as intended. One fixture that spec-objects-architecture calls **valid** gains a new Strict error
from an edge its author never wrote (FND-001).
