## Summary

Ticket: PLAT-1077 (epic PLAT-1076). PR: quire-rs#497, reviewed at `ff3dd0b`,
one commit on top of main `86cf84a`.

This is the release PR. It bumps the version from `0.47.1` to `0.48.0` and adds
a `[0.48.0]` CHANGELOG section. It has the same shape as the earlier release
commits `0d5727b` (v0.47.0) and `92dbebc` (v0.47.1). All three touch exactly
`CHANGELOG.md`, `Cargo.lock` and `Cargo.toml`. Each changes one line in each
manifest and adds a dated `## [x.y.z] — YYYY-MM-DD` section directly under an
empty `## [Unreleased]`.

Examined, clean:

- **Version locations.** `Cargo.toml` `[package] version` and the `quire-rs`
  entry in `Cargo.lock` both read `0.48.0`. `pyproject.toml` declares
  `dynamic = ["version"]` and maturin takes the version from Cargo. Apart
  from CHANGELOG history and two review files quoting the engine version
  they ran against, no `0.47.x` literal remains in any `.toml`, `.json`,
  `.py`, `.yaml` or `.md` file.
- **Lock consistency.** `cargo metadata --locked --offline` resolves the
  whole workspace without rewriting `Cargo.lock`, and it reports
  `quire-rs 0.48.0`. The tree stayed clean afterwards.
- **CHANGELOG coverage.** `git log v0.47.1..HEAD` lists exactly #494 (spec),
  #495 (implementation), #496 (PLAT-1090) and the release commit. The section
  cites all three PRs. Every claim was checked against the code at
  `86cf84a`:
  - the `range-in-trace-tag` diagnostic in `CoverageReport.diagnostics`;
  - range endpoints being kept out of `unmatched_tags` and mentions;
  - a legacy list that continues past a range still binding the rest
    (TC-1937);
  - obligation ids counting as declared (R2);
  - `coverage_matrix` fields, statuses and schema `$defs`;
  - the `published-schemas.json` re-mint, which touches only
    `coverage-v1.schema.json`;
  - `column` and `ignored` on `Symbol`, `SymbolRecord` and
    `VerifiesRelation`, with `skip_serializing_if = "is_false"` on the
    serialized ones;
  - the per-language ignored forms;
  - the spec ids FR-050-AC-47..51, FR-051-AC-27/28 and TC-1930..1944, all
    present at `af5ec21`.
- **Legacy range behaviour change.** The section says plainly: "Before
  0.48.0, a legacy `// Trace: A..B` tag bound `A`. It now binds neither `A`
  nor `B`." This matches FR-051-AC-28 and `legacy_ids` at `v0.47.1`, which
  split on commas only, so the id regex captured the left endpoint.
- **Bump level.** A minor bump in 0.x is right. The change alters binding
  results, which moves totals, `unbacked_rows` and `backed`. It also adds
  fields to the published `coverage-v1` output contract. The CHANGELOG
  header states that pre-1.0 breaking changes land in minor bumps.
