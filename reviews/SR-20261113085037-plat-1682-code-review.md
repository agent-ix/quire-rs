# Code review of the DiagramBlock fence line and CommonMark fence rules (quire-rs PR 673)

## Summary

Ticket: PLAT-1682. Code review with the Rust lane (rust-review, rust-style) over
`git diff origin/main...HEAD` at 713efca9 (4 files, +193/-64): the new
`DiagramBlock.line`, the shared `walk::Fence` type, and the heading walk and
diagram scanner moved onto it. The line arithmetic is correct and panic-free and
the CommonMark length, character, info-string and closing rules are right for
top-level fences. The defects: `query.rs` still holds a second fence
implementation with different rules, fences nested in list items are no longer
seen, and there are stale docs and some smaller points.

## Verdict

**FAIL** because of FND-001, a second implementation of the fence rule, which
code-review records as `high`. Everything else is medium or low. What passed:
frontmatter, BOM and CRLF line offsets are right by construction (`skipped` is a
prefix of `raw`, `body` is a suffix, and newlines are counted). `fence_run` cannot
panic, because the slices fall on ASCII boundaries. A CRLF `\r` is absorbed by
`rest.trim()` and `\s*`. A backtick info string with a backtick, a tilde info
string with a backtick, and an unclosed fence all behave correctly. Gates on the
head: `cargo fmt --check` clean; `cargo clippy --lib --tests -D warnings` clean;
`cargo test --lib -- query:: parser:: extract::` 188 passed;
`cargo test --test it -- parser semantic_boundary spec_dogfood corpus_case
trace_dogfood` 132 passed. Consumer impact of the walk change, measured with a
Python mirror of the old and new `walk_headings` over 66,241 Markdown files under
~/dev: 42 files change their heading set, none under `spec/`, and each change
matches CommonMark (38 service READMEs where a stray `` ```bash `` used to close
a fence, two copies of a reviewer SKILL.md with a `` ``` text `` line, and two
quire-exact SR files with a four-space-indented fence inside YAML). No external
crate in ~/dev uses `DiagramBlock`, `extract_diagrams` or `walk_headings`. No
vendoring, pins or SHA ceremony was added.

## New findings (disposition pass 1)

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-007 | low | The container stack only approximates CommonMark's list structure. A non-blank line indented below the item's content column always pops the item, but in CommonMark a lazy paragraph-continuation line keeps the item open. So a fence after a lazy line (`- item` / `text` / blank / an indented fence) is measured from column 0 and not recognised. Every line starting with a marker pushes a container, including an ordered marker that cannot interrupt a paragraph (`2026. …`). The second assertion of FR-007-AC-7's test (`- item\ntext\n\n    ```\n## H`) builds the lazy-line misreading in, and it passes under the CommonMark-correct reading too, so it cannot catch a regression. Measured impact: none on 16,068 spec/ files. | src/parser/walk.rs:485-509; src/parser/walk.rs:545-547 |
| FND-008 | low | Rule 5 of FR-007 says "a line indented less than that column ends the item". But while a fence is open the tracker never reads indentation, so a fence left unclosed in a list item runs to the end of the document. CommonMark ends the item there, and with it the fence, so the headings after it are lost. This matches main and FR-007 rule 4, but rules 4 and 5 disagree for this case and no AC covers it. | src/parser/walk.rs:486-492; spec/functional/FR-007-fenced-block-heading-walk.md:54-55 |

## New findings (disposition pass 2)

| ID | Severity | Summary | Refs |

| FND-009 | low | The sibling test only compares against the innermost item the line leaves. An ordered sibling of an outer item that follows a nested list (`1. one` / `   - nested` / `2. two`) is not taken as a sibling, because `col >= marker_col` is checked against the nested item only. The interrupt rule then drops the marker and the line is read as a lazy continuation, so the nested item's content column (5, not 3) stays in force. A following line indented 7 or 8 columns opens a fence that CommonMark treats as indented code. Minting is not affected, and no spec/ document in ~/dev changes. FR-007 rule 5 ("the item just left") leaves the case open. | src/parser/walk.rs:352-356 |
| FND-010 | low | The sibling assertion of the FR-007-AC-9 test (`["1. a", "2. b", "     ```"]`) cannot fail. With the sibling rule removed, `2. b` becomes a lazy continuation of `1. a`, the same content column 3 stays, and the five-space fence still opens. Use sibling markers of different widths (for example `9.` then `10.`, with the fence at the column only the second item allows) so the rule is actually exercised. | src/parser/walk.rs:576-580 |
